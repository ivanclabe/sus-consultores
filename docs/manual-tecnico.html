Arquitectura

Una aplicación React que corre en el navegador, sobre Supabase (login, base de datos y dos funciones de servidor) y Claude para la clasificación asistida. El Excel se lee en el navegador: nunca se sube al servidor.

Por qué la llave de Claude no está en el frontend

Todo lo que va en el frontend es visible para cualquiera que abra la app. Por eso la llave de Anthropic vive como secreto de Supabase y solo la leen las Edge Functions. El frontend solo conoce la URL del proyecto y la llave publicable, que está diseñada para ser pública y depende de las políticas de acceso (RLS) de la base.

Cuenta y proyecto en Supabase

Se recomienda un proyecto dedicado para SusConsultores. El proyecto de desarrollo actual está compartido con otras cuatro aplicaciones (ver capítulo 14).

Crear la cuenta

  1. Entrar a https://supabase.com y pulsar Start your project.
  2. Registrarse con GitHub o con correo. Si es con correo, confirmar el enlace que llega.
  3. Crear una organización (por ejemplo, SusConsultores) y elegir el plan. El gratuito sirve para empezar; en él los proyectos se pausan tras una semana sin uso.

Crear el proyecto

  1. En la organización, pulsar New project.
  2. Name: por ejemplo susconsultores-eeff.
  3. Database password: generar una contraseña fuerte y guardarla en un gestor de contraseñas. La pide la CLI al vincular el proyecto.
  4. Region: la más cercana a los usuarios. Para Colombia, South America (São Paulo) o una región de Estados Unidos (este).
  5. Pulsar Create new project y esperar uno o dos minutos a que termine de aprovisionarse.

Datos que se van a necesitar

Las llaves secret o service_role saltan todas las reglas de acceso. No van en .env.local ni en el repositorio. Esta app no las necesita.

5

API key de Claude (Anthropic)

La API de Claude se paga por uso, con créditos cargados por adelantado. La llave se muestra una sola vez al crearla.

  1. Entrar a https://console.anthropic.com y crear la cuenta (correo o Google). Confirmar el correo.
  2. Completar los datos de la organización cuando la consola los pida.
  3. Ir a Settings → Billing y cargar créditos. Sin saldo, la API responde con error.
  4. Recomendado: en Settings → Limits, definir un límite de gasto mensual.
  5. Ir a Settings → API Keys y pulsar Create Key. Nombrarla, por ejemplo, susconsultores-produccion.
  6. Copiar la llave en ese momento (empieza por sk-ant-) y guardarla en un gestor de contraseñas. No se puede volver a ver; si se pierde, se crea otra.
Modelo que usa la appclaude-sonnet-5, en la constante MODELO de cada función (supabase/functions/*/index.ts)
Dónde se configura la llaveSolo como secreto de Supabase: ANTHROPIC_API_KEY (capítulo 9)
Qué recibe ClaudeNombres, títulos y encabezados de hojas; códigos y nombres de cuentas. Nunca saldos.
Cuándo se llamaSolo cuando las reglas no alcanzan. Con el archivo de prueba de 2025-2024 no hizo falta ninguna llamada.
Decisión de SusConsultores

Aunque no viajan saldos, sí salen de la oficina los nombres de cuentas y de hojas de los clientes (por ejemplo, el nombre de un banco o de un tercero). Confirmar con la firma que eso es aceptable antes de activar la IA. Sin la llave, la app funciona igual con reglas y asignación manual.

git clone https://github.com/ivanclabe/susconsultores-estados-financieros.git
cd susconsultores-estados-financieros

# 2. Instalar dependencias (usa package-lock.json: versiones exactas)

# 3. Comprobar que compila

Variables de entorno

cp .env.example .env.local

Editar .env.local con los datos del capítulo 4:

VITE_SUPABASE_URL=https://abcdefghijkl.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_xxxxxxxxxxxxxxxxxxxx
VariableUso
VITE_SUPABASE_URLURL del proyecto. La usa el login, la base y las llamadas a las funciones.
VITE_SUPABASE_ANON_KEYLlave publicable. Pese al nombre, sirve tanto la sb_publishable_… como la anon clásica.
Se leen al compilar, no al ejecutar

Vite incrusta estas variables en los archivos compilados. Si cambian, hay que volver a compilar (npm run build o reconstruir la imagen de Docker). Sin ellas, la app muestra «Falta configuración». .env.local está en .gitignore: nunca se sube al repositorio.

Migrar la base de datos

Cuatro scripts en supabase/migrations/ crean todo el esquema. Se aplican en orden y solo una vez.

ArchivoQué hace
20260922120000_sc_init.sqlTablas base (empresas, rubros, reglas, informes, cuentas, clasificaciones, memoria, validaciones, auditoría) y reglas de acceso (RLS)
20260922120100_sc_catalogo_semilla.sqlCatálogo provisional: 19 rubros y 34 reglas de mapeo por código PUC
20260923090000_sc_extraccion_completa.sqlJerarquía completa, terceros, trazabilidad a celda y tablas de notas del archivo
20260925090000_sc_notas_hoja.sqlHoja de origen de cada nota

Opción A — con la Supabase CLI (recomendada)

# Una sola vez: crea supabase/config.toml (no toca migraciones ni funciones)
supabase init

# Iniciar sesión en la CLI (abre el navegador)
supabase login

# Vincular con el proyecto. Pide la Database password del capítulo 4
supabase link --project-ref abcdefghijkl

# Aplicar las migraciones pendientes. Muestra la lista y pide confirmación
supabase db push

Opción B — desde el panel de Supabase

En SQL Editor → New query, pegar y ejecutar (Run) cada archivo, en el orden de la tabla. Si más adelante se usa la CLI, registrar las cuatro versiones con supabase migration repair --status applied <versión>.

Verificar

En el SQL Editor:

select (select count(*) from sc_rubros)       as rubros,   -- 19
       (select count(*) from sc_reglas_mapeo) as reglas,   -- 34
       (select count(*) from information_schema.tables
         where table_schema = 'public' and table_name like 'sc\_%') as tablas; -- 11
No usar db push contra el proyecto de desarrollo actual

Es un proyecto compartido con otras apps y las cuatro migraciones ya están aplicadas ahí, con otras versiones: db push se detendría pidiendo reconciliar el historial. Los cambios nuevos en ese proyecto van por el SQL Editor.

Edge Functions y secreto de Claude

Opción A — con la CLI

# El secreto. Queda disponible de inmediato, sin volver a desplegar
supabase secrets set ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxx

# Las dos funciones (exigen una sesión válida: verify_jwt activo por defecto)
supabase functions deploy sc-identificar-hojas
supabase functions deploy sc-clasificar-cuentas

# Comprobar
supabase secrets list
supabase functions list

Opción B — desde el panel

  1. Edge Functions → Secrets: agregar ANTHROPIC_API_KEY con la llave del capítulo 5 y guardar.
  2. Edge Functions → Deploy a new function → Via Editor.
  3. Nombre exacto sc-identificar-hojas. Reemplazar el código de ejemplo por el de supabase/functions/sc-identificar-hojas/index.ts y desplegar.
  4. Repetir con sc-clasificar-cuentas.
  5. Dejar activa la verificación de JWT en ambas.

Verificar

curl -X POST https://abcdefghijkl.supabase.co/functions/v1/sc-identificar-hojas \
  -H "Authorization: Bearer sb_publishable_xxxx" -H "apikey: sb_publishable_xxxx" \
  -H "content-type: application/json" -d '{"hojas":[]}'
RespuestaSignifica
{"error":"Payload inválido."} (400)Todo bien. La función está desplegada y el secreto existe; solo rechazó el cuerpo vacío de la prueba.
…falta el secreto ANTHROPIC_API_KEY… (500)Falta el secreto: repetir supabase secrets set.
401 / Invalid JWTLa llave del encabezado no es de este proyecto.
404La función no está desplegada o el nombre no coincide.

La prueba de punta a punta con Claude se hace desde la app: si en el paso 2 se clasifican cuentas con «Usar el modelo» marcado y ninguna regla las cubre, deben aparecer propuestas con la etiqueta ia.

Usuarios y acceso

La app no tiene pantalla de registro: los usuarios los crea el administrador.

Crear un usuario

  1. Authentication → Users → Add user → Create new user.
  2. Correo y contraseña. Marcar Auto Confirm User para que pueda entrar de inmediato.
  3. Entregar las credenciales por un canal seguro.

Cerrar el registro público — obligatorio

En Authentication → Sign In / Providers, desactivar Allow new users to sign up.

Por qué es obligatorio

Las reglas de acceso dan acceso completo a cualquier usuario con sesión. Con el registro abierto, cualquiera que conozca la URL y la llave publicable (ambas visibles en la app) podría crearse una cuenta por la API y leer la información financiera de los clientes.

Opcional

En Authentication → URL Configuration, poner como Site URL el dominio de la app. Lo usan los correos de recuperación de contraseña.

Recorrido mínimo antes de publicar:

  1. Entrar con un usuario creado en el capítulo 10.
  2. Cargar un Excel real. La clasificación de hojas debe quedar completa, sin revisión pendiente.
  3. Revisar los tres tabs y las validaciones. Continuar.
  4. Clasificar las cuentas, confirmar y ver los estados. Activo = Pasivo + Patrimonio debe cuadrar.
  5. Aprobar y descargar el Excel.

Publicar el frontend

El repositorio trae un Dockerfile de dos etapas: compila con Node 20 y sirve los archivos con nginx. El docker-compose.yml está pensado para correr detrás de un proxy inverso que da el dominio y el HTTPS.

En el servidor (Linux con Docker)

# 1. Traer el código
git clone https://github.com/ivanclabe/susconsultores-estados-financieros.git
cd susconsultores-estados-financieros

# 2. Variables: se incrustan al compilar la imagen
cp .env.example .env.local
nano .env.local            # VITE_SUPABASE_URL y VITE_SUPABASE_ANON_KEY

# 3. La red "web" del proxy inverso (solo si no existe)
docker network create web

# 4. Compilar y levantar
docker compose up -d --build
PiezaComportamiento
Dockerfilenpm ci y npm run build en node:20-alpine; copia dist/ a nginx:alpine.
nginx.confPuerto 80, gzip, caché larga para /assets/, index.html sin caché (cada despliegue se ve de inmediato) y respaldo a index.html.
docker-compose.ymlUn servicio en la red externa web, sin puertos publicados: el proxy inverso (Traefik, Caddy, nginx-proxy…) lo alcanza por esa red y se encarga del dominio y el certificado.
Sin proxy inverso

Para exponer el contenedor directamente, agregar al servicio ports: ["8080:80"] y quitar la red externa. Así queda sin HTTPS: sirve para pruebas internas, no para producción.

Actualizar a una versión nueva

git pull
docker compose up -d --build

Si la versión trae migraciones o cambios en las funciones, aplicarlos antes (capítulos 8 y 9).

Alternativa: hosting estático

En Netlify, Vercel, Cloudflare Pages o similar: comando de build npm run build, carpeta de salida dist, y las dos variables VITE_… configuradas en el panel del servicio. La app no usa rutas, así que no necesita reglas de reescritura.

Reemplazar el catálogo institucional

El catálogo que viene con la app es provisional: está armado sobre el PUC colombiano. El de SusConsultores se carga en las tablas sc_rubros (rubros, sección, número de nota, orden) y sc_reglas_mapeo (prefijo PUC → rubro). La app lo lee al iniciar sesión: no hay que tocar código. 

-- Ejemplo: renombrar un rubro y moverlo de nota
update sc_rubros
   set nombre = 'Efectivo y equivalentes de efectivo', nota_numero = 4, origen = 'susconsultores'
 where codigo = 'EFECTIVO';

-- Ejemplo: una regla nueva, más específica (gana el prefijo más largo)
insert into sc_reglas_mapeo (prefijo, rubro_codigo, prioridad, origen)
values ('1330', 'OTROS_ACT_CTE', 10, 'susconsultores');

Las secciones válidas del Estado de Situación Financiera son activo_corriente, activo_no_corriente, pasivo_corriente, pasivo_no_corriente y patrimonio. Las del Estado de Resultados son ingresos, costos, gastos, otros_ingresos, otros_gastos e impuesto.

Seguridad y problemas conocidos

Lo que conviene resolver antes de usar la app con información real de clientes.

TemaSituaciónQué hacer
Proyecto compartido El proyecto de desarrollo también aloja otras cuatro apps con sus propios usuarios. Como las reglas dan acceso a cualquier usuario con sesión, los usuarios de esas apps podrían leer los datos de SusConsultores. Producción en un proyecto dedicado (capítulo 4).
Registro público Si queda activo, cualquiera puede crearse una cuenta y leer todo. Desactivarlo (capítulo 10).
Funciones de IA sin sesión Las funciones aceptan la llave publicable aunque no haya sesión, así que alguien con la app podría llamarlas y gastar créditos. Límite de gasto en Anthropic (capítulo 5). Mejora pendiente: que la función verifique que hay un usuario con sesión.
Sin .dockerignore COPY . . copia también node_modules y dist locales. Compilando en un Mac con dependencias instaladas, los binarios de macOS pisan los de Linux y el build puede fallar. Compilar desde un clon limpio en el servidor, o agregar un .dockerignore con node_modules y dist. No excluir .env.local: de ahí salen las variables del build.
Nombres heredados El servicio de docker-compose.yml se llama dark-kitchen, y los comentarios de nginx.conf mencionan rutas de otra app. Renombrar el servicio (por ejemplo, sus-consultores) y ajustar la regla del proxy. Los comentarios no afectan el funcionamiento.
Informes de prueba En la base de desarrollo quedan tres informes creados con una versión anterior de la extracción, con datos incorrectos. Descartarlos. No existen en un proyecto nuevo.
Plan gratuito Supabase pausa el proyecto tras una semana sin actividad y no hace respaldos. Plan pago para producción, o respaldos manuales.
